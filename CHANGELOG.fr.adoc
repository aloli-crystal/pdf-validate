== v0.39.0 — 2026-06-04 — Mode overprint des ICCBased CMYK (§ 6.2.4.2 t2)

=== Ajouté

* **`overprint_iccbased_cmyk_valid` (§ 6.2.4.2 t2)** — le
  `ContentStreamScanner` suit désormais l'état graphique (pile q/Q ;
  `gs` applique l'OPM et les drapeaux d'overprint OP/op d'une
  ExtGState ; `CS`/`cs` fixent l'espace couleur de trait/remplissage),
  piloté par les ressources résolues de chaque page. Une couleur
  ICCBased CMYK peinte avec overprint actif et OPM = 1 est une
  violation.
* `ContentStreamScanner#configure_overprint` + `overprint_cmyk_violation?`,
  avec `apply_overprint`/`check_overprint` et `STROKE_PAINT_OPS` /
  `FILL_PAINT_OPS`.
* Accesseur `Context` : `overprint_icc_cmyk_violations`, avec
  `overprint_extgstate_map` et `iccbased_cmyk_resource_names`.
* Specs : OPM=1 + overprint (détecté) ; OPM=0 (propre) ; OPM=1 sans
  overprint (propre).

=== Couverture (régénérée via `doc/gap-analysis/run.sh`)

§ 6.2.4.2 t2 quitte `not_covered_tests`. Le corpus conforme n'utilise
ni /OPM ni overprint : la règle ne s'y déclenche jamais (zéro faux
positif). § 6.2 passe à **55/56 (98 %)**. Couverture clause-level
totale : **138/144 → 139/144 (95 % → 96 %)**.

== v0.37.0 — 2026-06-04 — Codestream JPEG2000 (§ 6.2.8.3)

=== Ajouté

* **`Jpeg2000`** — un lecteur minimal des métadonnées structurelles
  JPEG2000 (boîtes JP2 + marqueur SIZ d'un codestream brut), qui ne
  lève jamais d'exception.
* **`jpeg2000_valid` (§ 6.2.8.3)** — pour les images /JPXDecode :
  nombre de canaux ∈ {1,3,4} (t1) ; avec plusieurs specs de couleur,
  une seule porte APPROX=1 (t2) ; METH du colr ∈ {1,2,3} (t3) ; espace
  couleur énuméré ≠ 19/CIEJab (t4) ; profondeur de bit uniforme dans
  1..38 (t5). t2/t3/t4 ignorés si l'image porte un /ColorSpace PDF (qui
  prime sur celui embarqué). Tolérant si les données sont illisibles.
* Accesseur `Context` : `jpeg2000_violations`, avec `jpx_filtered?`,
  `jpeg2000_issues` et `jpeg2000_colour_issues`.
* Specs : un JP2 conforme ; un nombre de canaux invalide (t1) ; EnumCS
  19 CIEJab (t4) ; le même exempté par un /ColorSpace PDF ; une
  profondeur de bit hors plage (t5).

=== Couverture (régénérée via `doc/gap-analysis/run.sh`)

§ 6.2.8.3 quitte `not_covered` (il était exclu pour ne pas gonfler via
son ancêtre § 6.2.8). Le corpus conforme n'utilise pas JPEG2000 : la
règle ne s'y déclenche jamais (zéro faux positif) ; les cas sont
forgés. § 6.2 passe à **54/56 (96 %)**. Couverture clause-level totale :
**132/144 → 137/144 (91 % → 95 %)**.

== v0.36.0 — 2026-06-04 — Interpréteur contenu→glyphes (§ 6.2.11.4.1 t2 & § 6.2.11.8)

=== Ajouté

Le `ContentStreamScanner` suit désormais la police courante (`Tf`) et
le mode de rendu de texte (`Tr`), capture les octets montrés par
`Tj`/`TJ`/`'`/`"` (en décodant les échappements des chaînes littérales
et hexadécimales) et les expose sous forme de « runs » de glyphes. Le
`Context` résout, pour une police Type0 Identity-H/V adossée à une
CIDFontType2, chaque CID montré en index de glyphe via /CIDToGIDMap.

* **`referenced_glyphs_present` (§ 6.2.11.4.1 t2)** — un glyphe
  référencé pour le rendu doit exister dans le programme embarqué
  (index dans les bornes).
* **`no_notdef_references` (§ 6.2.11.8)** — un opérateur de texte ne
  doit pas référencer le glyphe .notdef (index 0).
* Le texte en **mode de rendu 3 (invisible, p. ex. couche OCR) est
  exempté**, conformément à ISO 19005-2.
* Accesseurs `Context` : `referenced_glyph_absent_violations`,
  `notdef_reference_violations`, le `glyph_reference_scan` mémoïsé, et
  les aides `scan_type0_glyphs`, `page_font_resources`,
  `resolve_page_resources`.

=== Validation

Zéro faux positif sur les 36 PDF conformes (texte OCR réel avec la
couche de texte invisible) + Ghostscript — l'exemption du mode de rendu
3 est ce qui garde le corpus océrisé propre. § 6.2.11.4.1 t2 était déjà
comptée au niveau clause (cette version la rend réellement vérifiée) ;
§ 6.2.11.8 est nouvelle.

== v0.33.0 — 2026-06-04 — cmap du programme TrueType embarqué (§ 6.2.11.6 t1/t4)

== v0.32.0 — 2026-06-04 — Règles PDF/UA-1 par élément de structure (ISO 14289-1)

=== Ajouté

Premier palier per-élément du profil **pdf-ua-1**, piloté par un
marcheur d'arbre de structure (`each_struct_elem`, suivant
/StructTreeRoot → /K avec protection contre les cycles). Les règles
reproduisent exactement le profil PDF/UA-1 de veraPDF :

* **`struct_alt_text_present` (§ 7.3 / § 7.7)** — les éléments Figure
  et Formula doivent porter un /Alt non vide ou un /ActualText.
* **`struct_elements_have_parent` (§ 7.1 t12)** — chaque élément de
  structure doit avoir une entrée /P (parent).
* **`table_cells_in_row` (§ 7.2 t8/t9)** — les éléments TH et TD
  doivent être contenus dans un TR.
* **`notes_have_unique_id` (§ 7.9 t1/t2)** — les éléments Note doivent
  porter un /ID non vide et unique.

Accesseurs `Context` : `pdfua_alt_text_violations`,
`pdfua_struct_parent_violations`, `pdfua_table_cell_violations`,
`pdfua_note_id_violations`.

=== Tests

Un document balisé produit par le shard `pdf` (arbre Document → P) ne
déclenche aucune de ces règles (chaque StructElem a /P ; pas de
Figure/Note/cellule). Des fixtures forgées exercent chaque violation et
le cas propre Figure-avec-/Alt. Ce palier ne change pas le chiffre de
couverture PDF/A-2b (il vise le profil PDF/UA-1).

== v0.27.0 — 2026-06-04 — Filtre des images en ligne (§ 6.1.10)

=== Ajouté

* **`inline_image_filters_valid` (§ 6.1.10)** — le `ContentStreamScanner`

=== Différé

* **§ 6.1.8 t1** (les noms de polices / colorants / types de structure
  doivent être de l'UTF-8 valide après expansion des `#XX`) n'est *pas*
  implémenté ni compté : le parseur du shard `pdf` décode chaque
  séquence `#XX` en codepoint Unicode puis la réencode en UTF-8, si bien
  qu'un nom est toujours UTF-8 valide au niveau du modèle objet — la
  séquence d'octets d'origine est perdue. Détecter un nom non-UTF-8
  exigerait que le reader préserve les octets bruts, ou une corrélation
  byte-level entre positions de noms et rôles sémantiques.
