= pdf-validate
:toc: macro
:icons: font

Validateur de conformité PDF déclaratif pour la suite ISO PDF
d'ALOLI — jalon **J5** (cf. `pdf/doc/RATIONALE.adoc`). Un moteur
générique évalue des jeux de règles (YAML, un par profil) contre un
PDF parsé ; chaque règle est tracée à sa clause ISO, si bien qu'un
rapport tient lieu de piste d'audit. Un validateur ciblé, façon
veraPDF, restreint aux profils visés par ALOLI.

toc::[]

== État

Le moteur parse le PDF via `PDF::Reader` et trois analyseurs de plus
bas niveau (scanner d'octets bruts, scanner de content stream, parseurs
de programmes de police), puis évalue un jeu de règles YAML. Chaque
clause trace vers l'encodage ouvert veraPDF de la norme, et la
couverture est mesurée face au profil veraPDF 1.30.1 correspondant.

.Profils pris en charge
[cols="1,3,1",options="header"]
|===
| Profil | Norme | Couverture clause vs veraPDF

| `pdf-a-1b` | PDF/A-1b (ISO 19005-1:2005) | 118/129 = 91 %
| `pdf-a-2b` | PDF/A-2b (ISO 19005-2:2011) | 143/144 = 99 %
| `pdf-a-3b` | PDF/A-3b (ISO 19005-3:2012) | 145/146 = 99 %
| `pdf-ua-1` | PDF/UA-1 (ISO 14289-1)      | checks par élément
|===

Discipline : chaque règle est validée face à l'oracle veraPDF réel
avec **zéro faux positif** sur les corpus conformes. Quand la sémantique
exacte d'une règle ne peut être confirmée face à veraPDF, elle n'est
*pas* livrée mais documentée comme exclusion étayée (cf.
`doc/iso-19005-2-gap-analysis.adoc`).

== Installation

[source,yaml]
----
dependencies:
  pdf-validate:
    github: aloli-crystal/pdf-validate
    version: "~> 0.1.0"
----

== Utilisation bibliothèque

[source,crystal]
----
require "pdf-validate"

report = PDF::Validate.file("doc.pdf", profile: "pdf-a-2b")
puts report                # lisible
puts report.to_json        # machine
report.conformant?         # => true / false
report.failures            # => Array(Result) des règles échouées
----

== CLI

[source,console]
----
$ pdf-validate doc.pdf -p pdf-a-2b
$ pdf-validate doc.pdf --json
$ pdf-validate help
----

Codes de sortie : `0` conforme, `1` violations, `2` erreur usage / E-S.

== Ajouter des règles

Un jeu de règles est une liste YAML. Chaque règle nomme une
primitive du vocabulaire de checks du moteur et trace sa clause ISO :

[source,yaml]
----
- id: pdfa2-6.2.2-output-intent
  clause: "ISO 19005-2 § 6.2.2"
  title: "Document declares an OutputIntent"
  severity: error
  check: catalog_key_present
  args: ["OutputIntents"]
----

Vocabulaire actuel : `catalog_key_present`, `catalog_key_absent`,
`trailer_key_present`, `trailer_key_absent`, `xmp_contains`,
`xmp_matches`. On exprime une nouvelle exigence ISO en ajoutant une
primitive dans `src/pdf-validate/checks.cr`.
